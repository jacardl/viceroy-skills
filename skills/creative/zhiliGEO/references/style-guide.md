# 写作风格规范 & 版式参考

## 必须遵守
- **口语对话感**：读起来像作者在跟你喝茶聊天，不是写论文
- **具体 > 模糊**：用真实数字、真实案例、真实对话
- **立场鲜明**：作者有观点，不做理中客
- **用强比喻**：每个抽象概念必须配一个生活化的比喻

## 严禁出现
- ❌ 任何 emoji 或表情符号
- ❌ 任何 bullet point（`· ` 或 `- ` 开头的列表）
- ❌ 企业全名（用"某品牌""某平台"或品类词代替）
- ❌ "本文由 xxx 自动发布"等 branding
- ❌ 超过 3 个分隔符 `· · ·`（每篇 2–3 个最佳）
- ❌ 超过 5 个数据点（每个数据用深用透，不要堆砌）

## 用户草稿结构化内容降级规则

用户提供的草稿经常包含内部标签、表格、分类代号等结构化元素，写进公众号前必须全部转为自然 prose。

| 草稿中的形态 | 公众号里的处理方式 |
|---|---|
| "第一步：" "第二步：" "第三步：" | 改为句子里自然提到，如"第一步，加品牌限定词"→ "首先，在症状词后面加「什么品牌」" |
| "A类" "B类" "C1类" "C2类" 等内部标签 | 删除，用大白话描述结果，如"干预空间中等" "干预空间高" |
| "Y25-Y26" "Y27" 等内部时间标记 | 改为"旧的一年" "新的这一年"，不暴露内部时间线 |
| 表格（三行三对照等） | 整表删掉，改成一段自然叙述 |
| 任何 bullet point（· 或 - 开头） | 全部拆散，融入正文段落 |
| 带冒号的标签式标题 | 删冒号，改成自然句 |

**核心原则**：直隶按察使读者看不到内部分类和代号，只看到完整流畅的故事。

## 标点与格式
- 中文引号「」代替英文引号
- 数字用阿拉伯数字（"3年"不是"三年"）
- 百分比用 % 符号（"88%"不是"百分之八十八"）
- 英文术语第一次出现附中文翻译（"GEO（生成式引擎优化）"）

## 标题规范
| 位置 | 规则 |
|------|------|
| 主标题 | 16–24 字，含 GEO 或 AI 搜索相关词 |
| 副标题 | 可选，补充角度或悬念 |
| 风格 | 悬念感 > 概括感（「用户不搜了，AI 替你选了」 > 「GEO 与 SEO 的区别」）|

<!-- 开头钩子 -->
<p>事情是这样的。……</p>

<p style="text-align:center; color:#888; margin:30px 0;">· · ·</p>

<!-- 正文展开 -->

- `background:#f5f4ed` 固定背景色
- 结语段不加任何 CTA 或关注引导

## 文章结构（六模块）
1. 开头钩子（150–300字）：数据反常 / 认知矛盾 / 行业事件 / 直接设问 / 类比推进（每次选一种，不叠加）
2. 核心数据锚点（200–400字）：可溯源数字 + 一句话解读
3. 逻辑展开（800–2000字）：对比推进（SEO vs GEO / 旧 vs 新）
4. 行动框架（200–500字）：五步法 / 两种状态对比 / 三个误区
5. 行业信号（200–400字）：真实商业事件收尾
6. 结语钩子（80–150字）：回扣开头 + 认知升级 + 金句

**开头禁忌**：不用「朋友求助」「事情是这样的」「近年来」「随着 AI 的发展」——这些全部是已经用滥的套路。每篇文章从六种开头形态里选一种，写下一篇文章时换一种。
