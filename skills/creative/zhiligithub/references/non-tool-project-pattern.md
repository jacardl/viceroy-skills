# 非工具类项目（教科书 / 课程 / 数据集 / 文档）的六段式适配

> 触发条件：GitHub Trending 上的项目**不是**工具 / 框架 / AI 模型 / 命令行工具，而是**教育资源**（教科书、课件、习题集）、**数据集**、**文档**、**协议规范**、**论文合集**这类"读 / 学 / 引用"型项目。
>
> 实战样本：2026-06-15 `Introduction-to-Autonomous-Robots/Introduction-to-Autonomous-Robots`（CU Boulder 自主机器人开源教科书，2.7k stars / +276 today）。

## 核心原则

六段式的「6 个 H2 名字」是**模板**，不是死规。对非工具类项目，**每个 H2 都要重新框定"读者进来想读到什么"**，但总字数（1500-2000 字）、精简规则、renwei 黑话清单照常生效。

## 6 段模板的"通用版" vs "非工具适配版"

| 段 | 工具/框架默认 | 教科书/课程适配 | 数据集/文档适配 |
|---|---------------|------------------|------------------|
| 一 | 项目名称 + Star/语言/License | 项目名称 + Star/语言/License + **「这是一本 XX」** 钩子 | 项目名称 + **数据集规模**（行数 / GB / 类别数）|
| 二 | 项目介绍（痛点→方案→一句话定位）| 项目介绍（**领域怪圈**→项目起源→**双轨制 / 学术地位**）| 项目介绍（**数据空白**→收集方法→**与已有数据集的差异化**）|
| 三 | 架构设计（核心模块 + 数据流）| 架构设计（**章 / 部分 / 附录结构** + 教学法 + 配套资源）| 架构设计（**字段定义** + **数据格式** + **标注方式**）|
| 四 | 快速上手（`pip install` / `npm i`）| 快速上手（**在线读 / Overleaf / pdflatex 编译命令**）| 快速上手（**下载 / 加载 / 第一个查询**）|
| 五 | 实战场景（3-4 个失败→成功→创新弧线）| 实战场景（**学生自学 / 高校开课 / 工程参考 / 中文化 / 长期维护**）| 实战场景（**训练 SOTA / 评测 baseline / 行业研究**）|
| 总结 | 一句核心判断 + 留钩子 | 同 | 同 |

**关键差异**：
- 「快速上手」对工具 = 安装命令；对教科书 = 怎么**阅读**这本书（在线 / 编译 / 中文版）
- 「实战场景」对工具 = 真实项目里怎么用；对教科书 = 目标读者群（学生 / 教师 / 工程师）+ 长期维护信号
- 「架构设计」对工具 = 模块图；对教科书 = **目录结构 + 写作方法论**

## 教科书类项目的「必含 5 件事」

不管是哪本教科书，正文里**必须**出现这些信息（漏一个读者会觉得"没写到位"）：

1. **作者机构 + 出版方**（例：CU Boulder 4 教授 + MIT Press 2022 印刷版）
2. **License 的双层结构**（例：源码 CC BY-NC-ND 4.0 / 印刷版 MIT Press 收版权——开源教科书标配）
3. **结构 + 章节数 + 页数估计**（例：4 部分 25 章 ≈ 700 页）
4. **至少 3 种使用方式**（例：在线读 / Overleaf / 本地 pdflatex 编译）
5. **"还在维护"的硬证据**（例：2026-02-11 commit 修公式 3.34——比"社区活跃"实在 100 倍）

## 教科书类项目的「必删 3 件事」

- ❌ `pip install xxx` 风格的开头（教科书没安装步骤）
- ❌ "功能列表" 段（教科书的"功能"是章节，每章自己介绍；不要在开头堆 bullet）
- ❌ "性能跑分" 段（没有 benchmark）

**项目识别（第一步）**：

```bash
# 结论：教科书，不是工具
```

**H2 重新框定过程**：

| 段 | 工具的默认问法 | 教科书的问法 | 实战选择 |
|---|----------------|--------------|----------|
| 一 | 这个项目叫啥？ | 这本"书"叫啥？ | 一、项目名称（数据卡 + "12 年磨一本" 钩子）|
| 二 | 解决啥问题？ | 为啥要写这本？ | 二、项目介绍（教材怪圈 → CU Boulder 4 教授 → MIT Press 双轨）|
| 三 | 架构长啥样？ | 目录长啥样？ | 三、架构设计（4 部分 25 章 + 教学法 + QR 码视频）|
| 四 | 怎么装？ | 怎么读？ | 四、快速上手（在线 / Overleaf / pdflatex 三种方式）|
| 五 | 实战咋用？ | 谁在用？ | 五、实战场景（学生 / 高校 / 工程 / 中文化 / 还在改）|
| 总结 | 适合谁？ | 适合谁？ | 同（直接流，不写 H2）|

**正文里嵌入的具体数字**（renwei 要求的"具体观察代替套话"）：

- ❌"内容非常丰富" → ✅"4 部分 25 章，体量相当于一本 700 页左右的常规教材"
- ❌"作者很权威" → ✅"CU Boulder CS 系 4 位教授 + 2022 年 MIT Press 印刷版"
- ❌"社区很活跃" → ✅"2026 年 2 月 11 日 commit 修第 3.34 号公式——距离 2013 年首次提交已 12 年多"
- ❌"教学法很好" → ✅"odometry 在正运动学先露脸，到误差传播再被拎出来讲，到了定位讲卡尔曼滤波又出现了——每次复杂度往上提一层"

## 避坑提醒

**坑 1**：把教科书当工具写，跑题到"怎么部署"
- 错例："`git clone` 之后运行 `make`，可以部署一个在线课件网站"
- 正解：聚焦"**读者**怎么读这本书"，不是"**作者**怎么发布这本书"

**坑 2**：H2 名字照搬工具模板
- 错例：四、快速上手 写"先 fork 仓库，再 `pdflatex` 编译"——读者看到会想"我是来读教科书的，不是来当 LaTeX 排版工的"
- 正解：四、快速上手 写"三种读法：在线翻 / Overleaf 编译 / 本地 pdflatex"——读者选一个适合自己的就行

**坑 3**：漏掉"长期维护"信号
- 教科书类项目 12 年还没死本身就是新闻（教育资源的寿命是反向筛选器），**必须**写出"还在改"的硬证据
- 错例："作者持续维护中"
- 正解："2026-02-11 Roncone 提交 commit 修第 3.34 号公式"

**坑 4**：把"作者访谈"当主轴
- 教科书的"故事"在**章节**里，不在作者的私人故事里
- 错例：开篇写"Correll 教授在某次访谈中谈到……"（这是工具类项目的常见钩子套路）
- 正解：从"教材怪圈"切入——机器人方向的旧经典 + 商业 SDK 文档 → 痛点 → 引入项目

**坑 5**：「不是 X，不是 Y，不是 Z」三连排比
- 错例：「它不是工具，不是框架，不是模型——**它是一本教科书**」
- 问题：renwei 排比三连规则（"快、好、省" = 0）的扩展——三连否定也是机械的
- 修法：加入 hedging 动词稀释「也不是 AI 模型」/「也不是 SDK」让节奏自然

## 与主 SKILL.md 的关系

主 SKILL.md 第 186 行「标准六段式（单项目介绍）」是**工具类项目的默认模板**。本文档是其**非工具类适配扩展**。

**触发判断**：拿到 GitHub Trending 项目时，先看 `default_branch` + 主要文件类型 + description：

| 信号 | 判定 | 模板 |
|------|------|------|
| `.py` / `.js` / `.ts` / `.go` / `.rs` 为主 | 工具类 | 主 SKILL.md 默认 |
| `.tex` / `.ipynb` / `.md` / `.bib` 为主 | 教育/文档类 | **本文档** |
| `.parquet` / `.csv` / `.json` / `.tar` 为主 | 数据集类 | **本文档** |
| 多语言混合 + 主入口是 `book.tex` / `index.md` / `README.md` + 大量 figures | 教科书/课程 | **本文档** |
